# 双 EKF 三维融合定位扩展设计

> 文档状态：设计方案，尚未实施  
> 生成时间：2026-09-04 15:46  
> 适用工程：`robot_gps_localization`  
> 目标平台：具有坡道、起伏路面运动需求的地面机器人

## 1. 背景与结论

当前工程采用“局部 EKF + 全局 EKF”的双融合架构：

- FAST-LIO 和局部 EKF 提供连续、平滑但可能长期漂移的局部定位；
- GPS 提供低频全局绝对位置及航向；
- GPS 恢复平滑器负责在 GPS 消失和恢复时保持全局轨迹连续；
- 全局 EKF 融合局部运动增量和平滑后的 GPS 绝对观测；
- 当前 `map` 与 `odom` 通过单位静态 TF 固定重合。

该架构可以扩展到三维，不需要推翻重建。`robot_localization` 本身具有 15 维状态，FAST-LIO 内部也保留三维状态，现有 GPS 坐标转换、传感器杆臂补偿、协方差转换和路径发布代码大部分可以复用。

但三维升级不能只修改 `two_d_mode`。当前至少存在以下显式二维约束：

1. FAST-LIO 发布层将 z 强制压为 0；
2. 局部、全局 EKF 均开启 `two_d_mode`，且只选择 x、y、yaw；
3. GPS 全局里程计节点开启 `two_d_mode`；
4. GPS 恢复平滑器仅实现 SE(2)，并强制输出 z=0、roll=0、pitch=0；
5. 定位参考点使用 `base_footprint`，不符合完整 6DoF 机体坐标语义；
6. GPS 天线 z 向安装外参暂时为 0；
7. GPS 高度尚无独立的异常检测、恢复和调权机制。

对当前地面机器人，推荐的目标不是“GPS 全 6DoF 融合”，而是：

> 局部定位保留完整 xyz、roll、pitch、yaw；GPS 仅绝对修正 xyz 和 yaw；GPS 消失时全局轨迹平滑贴合局部三维轨迹，GPS 恢复时再平滑贴合 GPS 的 xyz/yaw。

这是一种适合地面机器人的“6DoF 局部状态 + 4DoF 全局校正”方案。

## 2. 术语与观测边界

### 2.1 Heading 与 Altitude

- `heading`：航向角，对应绕 z 轴的 yaw；
- `altitude`：高度，对应位置 z；
- heading 不能约束高度；
- 单天线 GNSS 通常不能提供 roll、pitch；
- 双天线 GNSS 通常可提供可靠 heading，但仍不一定能提供 roll、pitch；
- 只有具有完整姿态解算能力的多天线 GNSS/INS 才可能提供完整三轴姿态。

当前 `gps_to_utm_odometry_node` 的实际行为是：

- `NavSatFix.latitude/longitude` 转换为 UTM x/y；
- `NavSatFix.altitude` 直接作为 UTM z；
- `/imu_orientation` 中只提取 yaw，最终以 `RPY(0, 0, yaw)` 生成姿态；
- roll、pitch 协方差设置为未观测的大方差。

因此，现有 GPS 数据链路已经携带高度，但下游二维模式将其清零。

### 2.2 当前数据包的航向事实

`robot_data/all-data-8-23-4/metadata.yaml` 显示：

- `/imu_orientation`：`sensor_msgs/msg/Imu`，2617 条消息；
- `/heading`：`geometry_msgs/msg/QuaternionStamped`，0 条消息。

当前 launch 默认航向输入也是 `/imu_orientation`。后续不能仅依据 `/heading` 话题存在就认为其可用于融合。升级前必须确认实车数据的实际航向话题、消息类型、坐标约定、更新时间和协方差含义。

## 4. 目标架构

### 4.1 推荐状态来源

| 状态 | FAST-LIO/局部 EKF | GPS | 全局使用方式 |
|---|---:|---:|---|
| x | 是 | 是 | 局部连续传播，GPS 绝对修正 |
| y | 是 | 是 | 局部连续传播，GPS 绝对修正 |
| z | 是 | 条件启用 | 局部连续传播，可靠 RTK 高度绝对修正 |
| roll | 是 | 否 | 始终由 FAST-LIO/IMU 提供 |
| pitch | 是 | 否 | 始终由 FAST-LIO/IMU 提供 |
| yaw | 是 | 是 | 局部连续传播，可靠 heading 绝对修正 |

GPS z 必须设计为可配置观测：

- RTK Fixed、高度方差可信、垂直基准明确：融合 GPS z；
- 普通单点定位、z 抖动明显或高度基准不明确：不融合 GPS z，z 始终使用 FAST-LIO；
- 介于两者之间：GPS z 使用较大协方差和更慢的恢复速度。

### 4.2 目标 TF 结构

推荐使用：

```text
map
  |
  | 固定单位TF（保留当前策略）
  v
odom
  |
  | 动态完整6DoF定位
  v
base_link
  +-- livox_imu
  +-- livox_frame
  +-- gps

base_footprint
  仅作为二维导航所需的地面投影坐标系，不作为三维融合状态主体
```

三维融合状态的 `base_link_frame` 应由 `base_footprint` 改为 `base_link`。原因是 `base_footprint` 按 ROS 常用语义应是不含 z、roll、pitch 的地面投影，而 `base_link` 才表示机器人机体的完整空间位姿。

### 4.3 `map` 与 `odom` 固定重合的适用边界

当前固定单位 `map -> odom` 策略在地面三维场景中仍可保留，但必须满足：

1. `map` 和 `odom` 都使用 ENU/REP-103，z 轴向上；
2. 两坐标系都与重力方向对齐；
3. FAST-LIO 初始 z 与 GPS 局部高度原点一致，通常均初始化为 0；
4. GPS 恢复产生的位置与 yaw 校正必须经过平滑器，不能瞬间跳变；
5. 局部和全局 EKF 不得重复发布同一条 TF。

如果未来平台扩展为无人机、船舶或需要严格隔离“连续局部 TF”和“跳变全局修正”，应切换到标准动态 `map -> odom` 架构。该变化不是当前地面三维升级的必要条件。

## 5. 各模块改造设计

### 5.1 FAST-LIO 发布层

相关文件：

- `src/FAST_LIO_ROS2/config/mid360.yaml`
- `src/FAST_LIO_ROS2/src/laserMapping.cpp`

当前配置：

```yaml
publish:
  flatten_z: true
```

目标配置：

```yaml
publish:
  flatten_z: false
```

该开关只影响发布的里程计、轨迹及世界坐标点云，不改变 FAST-LIO 内部三维状态估计。现有代码已经发布完整四元数，并从滤波器状态矩阵填充完整 6×6 位姿协方差。

实施时需要同时检查：

- `/Odometry.pose.pose.position.z` 是否随坡度合理变化；
- 四元数对应的 roll/pitch 是否与车辆倾斜方向一致；
- 点云、里程计和 Path 是否使用相同 `world_frame`；
- FAST-LIO z 是否存在长期漂移或初始化瞬态。

### 5.2 局部 EKF

相关文件：`src/robot_ekf_localization/config/ekf_local.yaml`

目标配置框架：

```yaml
two_d_mode: false
base_link_frame: base_link
world_frame: odom

odom0_config: [
  true,  true,  true,   # x, y, z
  true,  true,  true,   # roll, pitch, yaw
  false, false, false,  # vx, vy, vz
  false, false, false,  # vroll, vpitch, vyaw
  false, false, false   # ax, ay, az
]
odom0_differential: false
odom0_relative: false
```

第一阶段只融合 FAST-LIO 的完整位姿，不立即启用 twist 或重复融合 `/livox/imu`。原因是 FAST-LIO 已经内部融合该 IMU；将同源数据再次作为独立观测输入 EKF，会破坏独立噪声假设并造成过度置信。

过程噪声应重新按三维状态调整：

- z 过程噪声不再保持二维占位值；
- roll/pitch 过程噪声应允许车辆坡道姿态变化；
- z、roll、pitch 的初始估计协方差应与 FAST-LIO 初始稳定时间匹配；
- 不应仅复制 x/y/yaw 的数值到新增维度。

### 5.3 GPS UTM 里程计

相关文件：

- `src/robot_odom_transform/src/gps_to_utm_odometry_node.cpp`
- `src/robot_odom_transform/config/gps_transform.defaults.yaml`

现有代码已输出：

```text
x = UTM easting
y = UTM northing
z = NavSatFix.altitude
orientation = yaw-only quaternion
```

主体转换逻辑可以保留，但建议将位置方差参数拆分为：

```yaml
horizontal_position_variance_floor: 0.01
vertical_position_variance_floor: 0.25
unknown_horizontal_position_variance: 4.0
unknown_vertical_position_variance: 25.0
```

具体默认值必须依据接收机规格和实测静态数据确定，上述数值仅说明垂直方差应独立配置，不能直接作为最终标定值。

航向输入仍然只用于 yaw：

- `north_clockwise` 输入转换到 ENU yaw；
- 保留 `orientation_yaw_offset` 标定；
- roll/pitch 继续设置为未观测大方差；
- 若未来改用 `/heading`，需要增加 `QuaternionStamped` 输入支持或单独的适配节点。

### 5.4 GPS 全局原点与杆臂补偿

相关文件：

- `src/robot_odom_transform/src/gps_global_odometry_node.cpp`
- `src/robot_odom_transform/config/gps_transform.defaults.yaml`

目标修改：

```yaml
gps_global_odometry_node:
  ros__parameters:
    two_d_mode: false
    child_frame_id: base_link
```

现有初始化已经对初始 UTM x、y、z 求平均，并将其整体作为局部 `map` 原点。因此，关闭二维模式后，GPS 输出的 z 会自然变成相对初始高度，而不是巨大的绝对海拔值。

现有原点旋转只消除初始 yaw，不消除初始 roll/pitch。对于地面机器人这是正确选择：`map` 应保持重力对齐，而不应随着车辆恰好停在坡面上的初始 roll/pitch 倾斜。

现有代码已经执行完整三维 GPS 天线到融合参考点的刚体变换和协方差雅可比变换，可以继续复用。

### 5.5 URDF 与传感器安装外参

相关文件：`config/urdf/robot.urdf`

三维定位必须使用真实的六自由度静态外参：

```xml
<joint name="base_link_to_gps" type="fixed">
  <parent link="base_link"/>
  <child link="gps"/>
  <origin xyz="实测x 实测y 实测z" rpy="实测roll 实测pitch 实测yaw"/>
</joint>
```

当前 GPS 安装外参为：

```text
xyz = [-1.193227, -0.405604, 0.000000]
yaw = +pi/2
```

其中 z=0 是由于已有数据包无法观测天线相对 IMU 的高度，并非真实安装值。三维实施前必须人工测量或标定：

- `base_link -> gps` 的 x/y/z；
- GPS 天线/航向设备的安装 yaw；
- 如果航向设备坐标轴不水平，还需要安装 roll/pitch；
- `base_link -> livox_imu` 的真实平移和旋转；
- `livox_imu -> livox_frame` 的完整外参。

在有 roll/pitch 的坡道场景中，错误的 GPS 天线高度会通过杆臂旋转产生明显的水平和垂直位置误差，因此 z 外参不能继续使用占位值。

### 5.6 GPS 质量过滤

相关文件：`src/robot_odom_transform/src/gpgga_filter_node.cpp`

当前过滤器仅检查：

- 经纬度和高度是否为有限值；
- `NavSatStatus` 是否达到要求；
- x/y 方差是否合法；
- 连续有效帧数是否满足恢复要求。

三维版本建议增加以下参数：

```yaml
max_horizontal_variance: 参考实测确定
max_vertical_variance: 参考实测确定
max_altitude_jump: 参考GPS频率和车辆能力确定
max_vertical_speed: 参考车辆最大坡度和速度确定
vertical_recover_frame_count: 大于等于水平恢复帧数
require_known_vertical_covariance: true
```

过滤规则建议：

1. z 方差必须有限且非负；
2. 启用 GPS z 融合时，应要求垂直协方差已知；
3. 高度单帧跳变量超过阈值时拒绝该帧 z；
4. 由高度差和时间差得到的垂直速度超过车辆物理能力时拒绝该帧 z；
5. 水平 GPS 可以恢复而高度暂未恢复，二者状态不必强绑定；
6. RTK 状态下降时可以保留 x/y/yaw，单独暂时禁用 z；
7. 所有拒绝原因应发布诊断信息和节流日志。

### 5.7 GPS 恢复平滑器

相关文件：`src/robot_ekf_localization/scripts/gps_recovery_smoother_node.py`

当前节点只处理 SE(2)：

```text
pose = (x, y, yaw)
correction = (dx, dy, dyaw)
```

并在正常输出和局部回退输出中显式设置：

```text
z = 0
orientation.x = 0
orientation.y = 0
```

推荐改为 4DoF 全局校正，而不是让 GPS 控制完整姿态：

```text
local pose      = (x_l, y_l, z_l, q_l)
global GPS pose = (x_g, y_g, z_g, yaw_g)
correction      = (dx, dy, dz, dyaw)
output attitude = roll_local, pitch_local, yaw_corrected
```

同步时刻下的理论校正可以写为：

```text
C = T_map_base(GPS) * inverse(T_odom_base(local))
```

实际应用前将 C 投影到 4DoF：保留三维平移和 yaw，舍弃由 GPS 计算得到的 roll/pitch。最终输出由校正 C 与局部位姿组合得到。

建议状态机保持四个阶段：

#### TRACKING_GPS

- GPS 连续有效；
- x/y/yaw 强跟踪 GPS；
- z 仅在高度质量状态有效时跟踪 GPS；
- roll/pitch 透传局部定位；
- GPS z 失效不应导致整个 GPS 状态立即丢失。

#### GPS_LOST_TRANSITION

- GPS 超时后启动；
- 在 `loss_transition_duration` 内将 dx/dy/dz/dyaw 平滑衰减到局部基准；
- 过渡结束后全局定位与局部三维轨迹重合；
- 输出及一阶变化保持连续。

#### LOCAL_FALLBACK

- GPS 不可用；
- 绝对观测直接由局部 x/y/z 和完整姿态生成；
- 全局 EKF 继续跟随局部轨迹；
- 局部自身的长期漂移在该阶段无法被外部绝对观测消除，这是预期行为。

#### GPS_RECOVERY

- GPS 满足连续有效帧和时间同步条件后启动；
- 平滑更新 dx/dy/dz/dyaw；
- 水平、垂直、航向分别限速；
- 达到时间和残差门限后进入 `TRACKING_GPS`；
- z 尚未通过质量门限时，只恢复 x/y/yaw，不阻塞水平定位恢复。

建议新增或拆分参数：

```yaml
max_horizontal_correction_rate: 1.0
max_vertical_correction_rate: 0.2
max_yaw_correction_rate: 0.35

tracking_horizontal_tolerance: 0.05
tracking_vertical_tolerance: 0.15
tracking_yaw_tolerance: 0.02

vertical_correction_time_constant: 2.0
use_gps_altitude: true
```

这里的数值是接口示例，不应未经数据评估直接作为最终参数。

四元数处理建议：

1. 从局部四元数提取 roll、pitch、yaw；
2. 只对 yaw 校正量进行最短角归一化和限速；
3. 使用 `setRPY(local_roll, local_pitch, corrected_yaw)` 重建输出姿态；
4. 若未来改为完整 SE(3) 外部姿态观测，再采用四元数 SLERP，避免直接线性插值四元数。

### 5.8 全局 EKF

相关文件：`src/robot_ekf_localization/config/ekf_global.yaml`

目标框架：

```yaml
two_d_mode: false
base_link_frame: base_link
world_frame: odom

# 局部完整位姿被转换为相邻帧运动增量
odom0_config: [
  true,  true,  true,
  true,  true,  true,
  false, false, false,
  false, false, false,
  false, false, false
]
odom0_differential: true
odom0_relative: false

# GPS绝对修正：xyz + yaw
odom1_config: [
  true,  true,  true,
  false, false, true,
  false, false, false,
  false, false, false,
  false, false, false
]
odom1_differential: false
odom1_relative: false
```

若 GPS 高度暂不满足要求，将 `odom1_config` 的 z 设置为 `false`，其他设计保持不变。

全局 EKF 的三维调参原则：

- GPS 垂直协方差通常应大于水平协方差；
- 不要通过极小 z 协方差强迫全局轨迹逐点贴合噪声高度；
- GPS 恢复平滑器负责连续性，EKF 负责统计融合，两层参数不能同时过度激进；
- 局部差分位姿负责 GPS 中断传播，不应与 GPS 绝对原点竞争；
- roll/pitch 只来自局部链路，GPS 对应配置必须为 `false`；
- 重新设置 z、roll、pitch、vz、vroll、vpitch 等状态的过程噪声和初始估计协方差。

`robot_fusion_path` 已复制完整 Pose，并使用 dx/dy/dz 计算路径点间距离，能够直接支持三维 Path，无需结构性重写。

RViz2 建议同时显示：

- FAST-LIO 原始三维点云和 Path；
- `/local_path`；
- `/gps_path`；
- `/global_path`；

## 6. 高度基准设计

### 6.1 不直接使用绝对海拔作为局部 z

`NavSatFix.altitude` 通常可能表示椭球高，而地图或人工测量可能使用正高。二者不能在没有大地水准面模型的情况下直接混用。

当前 `gps_global_odometry_node` 会使用初始化阶段的平均 UTM x/y/z 建立局部 `map` 原点，因此输出 z 是相对初始高度。对于本工程，这是最简单且合理的做法：

```text
z_map = z_gps_current - mean(z_gps_initial)
```

同时 FAST-LIO 一般从 z=0 开始，因此二者起点可以统一。

### 6.2 初始高度初始化条件

建立高度原点时应满足：

- GPS 处于期望定位状态；
- 初始采样期间机器人静止或运动足够缓慢；
- z 方差低于阈值；
- 连续采样数量满足要求；
- 对异常高度使用中位数、截尾均值或离群值剔除，而不是无条件平均。

### 6.3 垂直观测降级

建议将 GPS 可用性拆分为：

```text
horizontal_valid
heading_valid
vertical_valid
```

允许出现以下正常状态：

| 水平 | 航向 | 高度 | 融合策略 |
|---:|---:|---:|---|
| 有效 | 有效 | 有效 | GPS 修正 xyz/yaw |
| 有效 | 有效 | 无效 | GPS 修正 xy/yaw，z 跟随 FAST-LIO |
| 有效 | 无效 | 有效 | GPS 修正 xyz，yaw 跟随 FAST-LIO |
| 无效 | 无效 | 无效 | 全局定位平滑回退并跟随局部完整位姿 |

## 7. 建议实施顺序

### 阶段 A：数据质量基线，不改变现网输出

1. 从 rosbag 导出 FAST-LIO z、roll、pitch；
2. 统计静止和行驶状态下 GPS altitude 的均值、标准差、最大跳变；
3. 检查 `NavSatFix.position_covariance[8]` 是否真实有效；
4. 确认 `/imu_orientation` 航向来源和坐标约定；
5. 确认 `/heading` 在实车是否有数据；
6. 测量 GPS、IMU、LiDAR 相对 `base_link` 的三维外参。

### 阶段 B：仅恢复局部三维定位

1. FAST-LIO 设置 `flatten_z=false`；
2. 局部 EKF 设置 `two_d_mode=false`；
3. 局部 EKF 融合 FAST-LIO xyz/roll/pitch/yaw；
4. 融合参考点切换到 `base_link`；
5. 暂不改变全局 EKF 和 GPS 逻辑；
6. 验证坡道局部轨迹、点云和姿态一致性。

该阶段应允许通过参数一键恢复二维模式，便于 A/B 对比。

### 阶段 C：GPS 三维位置链路

1. GPS 全局里程计关闭 `two_d_mode`；
2. 标定并更新 GPS z 杆臂；
3. 增加垂直协方差和高度跳变过滤；
4. 验证 `/odometry/gps.position.z` 是以初始位置为零点的相对高度；
5. 暂不送入全局 EKF，只对比 GPS z 和 FAST-LIO z。

### 阶段 D：4DoF GPS 恢复平滑

1. 将平滑器由 SE(2) 扩展为 xyz+yaw 校正；
2. roll/pitch 始终继承局部定位；
3. 增加独立垂直质量状态和垂直限速；
4. 仿真 GPS 整体中断、仅高度失效、仅 heading 失效；
5. 验证所有切换点的位置和姿态连续性。

### 阶段 E：全局三维 EKF

1. 全局 EKF 设置 `two_d_mode=false`；
2. 局部输入启用 xyz/roll/pitch/yaw 差分；
3. GPS 输入先启用 xy/yaw；
4. GPS 高度通过验收后再启用 z；
5. 基于回放数据调节 z 协方差、过程噪声和恢复速率；
6. 完成长时间闭环、上下坡和 GPS 遮挡测试。

## 8. 验收标准

### 8.1 基础坐标与姿态

- 启动静止时 local/global/GPS 相对高度均接近 0；
- 上坡时 z 与 pitch 符号符合 REP-103；
- 下坡或返回起点时高度趋势合理，无持续单向下沉；
- 点云、里程计、Path 和 TF 在相同坐标系下没有分层或重复旋转；
- `base_link -> gps` 杆臂补偿在转弯和坡道上方向正确。

### 8.2 GPS 正常

- x/y 在合理滞后内贴合 GPS；
- GPS z 有效时 global z 平滑贴合 GPS 相对高度；
- roll/pitch 不因 GPS 更新发生突变；
- heading 更新不导致 roll/pitch 丢失；
- 全局轨迹没有由 GPS 高频噪声造成的明显锯齿。

### 8.3 GPS 消失

- 超时判定符合 `gps_timeout`；
- global 向 local 的 x/y/z/yaw 过渡连续；
- 过渡后 global 与 local 三维轨迹贴合；
- roll/pitch 始终连续；
- 不产生 z=0 突然压平或四元数重置。

### 8.4 GPS 恢复

- 满足连续有效帧后才进入恢复；
- x/y、z、yaw 分别受最大校正速率限制；
- 高度无效时不阻塞水平 GPS 恢复；
- 恢复结束前后位置和姿态无阶跃；
- 最终 global 在允许误差内贴合有效 GPS 轨迹。

### 8.5 定量建议

最终阈值应依据车辆和传感器指标确定，至少记录以下指标：

- GPS 中断前后位置、z、yaw 最大瞬时跳变量；
- GPS 恢复阶段最大水平/垂直校正速度；
- 静止 GPS altitude 标准差和 95% 分位误差；
- local 与 GPS 的高度增量相关性；
- 闭环回到起点时 local/global/GPS 的 xyz 残差；
- roll/pitch 连续性和最大角速度；
- 每种 GPS 状态下 EKF innovation、拒绝次数和诊断状态。

## 9. 风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| GPS 高度噪声大 | global z 抖动或缓慢漂移 | 独立垂直协方差、限速、门限；必要时禁用 GPS z |
| 高度基准不一致 | local/GPS z 存在固定或时变偏差 | 统一使用相对初始高度；明确椭球高/正高 |
| 天线 z 杆臂错误 | 坡道、转弯时 xyz 周期性偏差 | 实测完整 xyz/rpy 外参 |
| 重复融合同一 IMU | EKF 过度置信、姿态异常 | FAST-LIO 已融合 IMU 时，局部 EKF 初期只融合其位姿 |
| 平滑器继续使用 SE(2) | z 被清零、roll/pitch 丢失 | 先完成 4DoF 平滑器再启用全局三维 EKF |
| `/heading` 无实际消息 | yaw 无法更新 | 使用确认有数据的 `/imu_orientation` 或实现话题适配 |
| GPS course heading 低速失效 | 静止或低速 yaw 跳变 | 区分双天线航向与地速航向；增加速度/质量门限 |
| TF 重复发布 | RViz 抖动、TF tree 冲突 | 明确每条动态 TF 的唯一发布者 |
| 直接一次性启用所有维度 | 难以定位误差来源 | 按局部三维、GPS 高度、平滑器、全局 EKF 分阶段启用 |

## 10. 回退策略

所有三维能力应保留参数化开关，出现问题时可以快速回退：

```yaml
# FAST-LIO二维输出回退
flatten_z: true

# EKF二维回退
two_d_mode: true

# GPS高度回退
use_gps_altitude: false
```

建议保留独立配置文件，而不是反复覆盖已验证的二维参数：

```text
ekf_local.yaml       # 当前稳定二维配置
ekf_global.yaml      # 当前稳定二维配置
ekf_local_3d.yaml    # 三维实验配置
ekf_global_3d.yaml   # 三维实验配置
```

launch 层增加 `localization_mode:=2d|3d` 或明确的配置文件参数，使 rosbag 回放可重复对比。

## 12. 最终建议

本工程最合理的近期目标是地面三维融合，而不是无条件的完整 GPS 6DoF：

```text
FAST-LIO：完整 xyz + roll/pitch/yaw
Local EKF：完整 6DoF 连续定位
GPS：绝对 xy + 可选z + heading/yaw
Recovery smoother：dx/dy/dz/dyaw 平滑校正
Global EKF：局部6DoF增量 + GPS 4DoF绝对修正
Fusion frame：base_link
map/odom：当前阶段继续固定单位重合
```

其中最关键的实施前置条件不是 EKF 参数，而是：

1. 确认 GPS altitude 的真实性、基准和协方差；
2. 实测 GPS 天线 z 向杆臂及完整安装外参；
3. 将 GPS 恢复平滑器从 SE(2) 改造成至少支持 xyz+yaw；
4. 分阶段验证，最后才允许 GPS z 进入全局 EKF。

满足这些条件后，当前双融合架构能够平滑扩展到上下坡三维定位，同时保留已经验证有效的 GPS 消失贴合局部、GPS 恢复贴合全局观测的工作机制。
